`app.start()`가 성공했다고 해서 커널이 알아서 앱을 멈추지는 않아요. 애초에 `app.stop()`이 필요한지 여부도 여러분이 직접 결정하면 돼요. 금방 끝나는 CLI 스크립트나 탭을 닫으면 함께 사라지는 전체 페이지 브라우저 그래프는 OS나 브라우저 탭이 모든 리소스를 회수해 가니 굳이 `stop()`을 부를 필요가 없죠. `onDispose()`와 `app.stop()`이 빛을 발하는 순간은 **그래프가 끝난 뒤에도 무언가 계속 살아남는 환경**이에요. 포트나 DB 풀을 붙잡고 있는 상주 서버, 격리된 테스트 케이스, 혹은 페이지는 유지된 채 마운트 해제되는 UI 위젯이 대표적이에요.

## 주입 차단과 LIFO 역순 정리

`app.stop()`을 호출하면 정확히 아래 순서대로 두 가지 일이 일어나요.

1. **앱 전체의 `inject()`를 동기적으로 즉시 닫아요:** 마이크로태스크가 단 하나도 실행되기 전에 앱 안의 모든 `inject()` 핸들이 영구적으로 닫혀요. 이후에 일어나는 모든 `inject()` 호출은 — 이미 캐시된 인스턴스를 꺼내려 하거나 위 예제의 `service.read()`처럼 프라이빗 서브트리 안에서 호출하더라도 — 즉시 `Cannot inject after the app has stopped` 에러를 던져요.
2. **`onDispose` 훅을 최신 등록순(LIFO)으로 실행해요:** 등록된 순서의 역순으로 하나씩 차례대로 실행돼요. 예를 들어 DB 커넥션 풀이 먼저 등록되고 HTTP 서버가 나중에 등록됐다면, `stop()`은 HTTP 서버를 먼저 닫은 뒤 DB 커넥션 풀을 정리해요.

정리 훅이 실행될 때는 이미 `inject()`가 닫혀 있기 때문에, `dispose.ts`의 `const store = inject(storeRef)`처럼 **`onDispose()`를 등록하기 전에 필요한 의존성을 미리 지역 변수에 담아 두어야 해요.**

`app.stop()`을 여러 번 또는 동시에 호출하더라도 멱등성이 보장되어 똑같은 `Promise`를 반환하며 각 훅은 딱 한 번만 실행돼요. 한 번 멈춘 앱에서 다시 `app.start()`를 호출하면 `Cannot start an app that has been stopped` 에러로 거부돼요.

## await using으로 자동 정리하기

모든 `App`은 `AsyncDisposable`을 구현해요. 런타임에 네이티브 `Symbol.asyncDispose`가 있으면 `[Symbol.asyncDispose]`를 정의하고, 네이티브 심볼이 없는 구형 런타임에서는 TypeScript 5.2+의 다운레벨 `await using` 변환 코드가 그대로 찾을 수 있도록 `[Symbol.for('Symbol.asyncDispose')]`로 폴백해요.

테스트, CLI 잡, 혹은 `runScopedTask()` 같은 요청 단위 워커에서 `await using app = bootstrapApp(...)`이라고 적어 두면 블록을 빠져나갈 때 — 블록 중간에서 예외가 터지더라도 — `app.stop()`이 자동으로 `await`돼요.

## 런타임별 종료 시그널 연결하기

종료 시그널은 JavaScript 런타임마다 방식이 제각각이라 커널이 몰래 전역 리스너를 등록하지 않아요. 실행 환경에 맞는 생명주기 트리거에 `app.stop()`을 연결해 주세요.

| 런타임 | 종료 트리거 | 비동기 정리 대기 여부 |
| --- | --- | --- |
| Node.js, Bun | `process.on('SIGINT' \| 'SIGTERM', handler)` | 핸들러가 프로세스를 살려 두면 `await` 가능해요 |
| Deno | `Deno.addSignalListener('SIGINT', handler)` | `await` 가능해요 |
| 브라우저 부분 앱 | 직접 관리하는 언마운트 시점(React `useEffect`, Vue `onScopeDispose`, 라우터 이동) | `await` 가능해요 |
| 브라우저 페이지 전체 | `addEventListener('pagehide', handler)` | 보장되지 않아요 — 동기 훅으로만 작성하세요 |
| Web Worker | `worker.terminate()` 전에 호스트가 보내는 종료 메시지 | 호스트가 종료 완료를 기다린 뒤 terminate할 때만 가능해요 |
| 서버리스, 엣지 | 앱 스코프를 묶어 둔 요청 또는 함수 호출이 끝나는 시점 | 플랫폼의 keep-alive API 지원 여부에 따라 달라요 |

환경별로 실무에서 챙겨 두면 좋은 팁이에요.

- **Node.js & Bun (`node-server.ts`):** `SIGINT` / `SIGTERM` 리스너는 반드시 `await app.start()` *이전에* 등록하세요. `bootstrapApp()`은 프로바이더를 미리 실행하지 않기 때문에 `3000`번 포트가 열리기 전에 `app` 핸들이 이미 준비되어 있어요. Deno에서도 똑같은 그래프에 리스너만 `Deno.addSignalListener('SIGINT', () => void app.stop())`으로 바꿔 끼우면 돼요.
- **브라우저 위젯 (`browser-unmount.ts`):** 가능하면 브라우저 그래프는 직접 언마운트를 제어하는 컴포넌트나 라우트 단위로 묶어 주세요(`await ready; await app.stop()`). 페이지가 살아 있는 상태에서 정리하므로 비동기 정리 훅도 끝까지 안전하게 기다릴 수 있어요.
- **브라우저 탭 닫기 (`browser-pagehide.ts`):** 뒤로/앞으로 가기 캐시(bfcache)를 깨뜨리거나 건너뛰어지기 쉬운 `beforeunload` 대신 `pagehide`를 쓰세요. 다만 `pagehide`에서도 브라우저는 `async` `Promise`가 끝나기 전에 페이지를 폐기하는 경우가 흔하니, 언로드 훅은 `navigator.sendBeacon()`처럼 반드시 동기 코드로만 작성해야 해요.

## 정리 훅 규칙, 기동 실패 롤백, 그리고 한계

`onDispose` 훅을 작성할 때는 아래 불변 규칙들을 꼭 기억해 주세요.

- **등록 가능 구간:** `onDispose()`는 자기 자신의 팩토리가 실행 중이고 아직 `stop()`이 호출되기 전에만 부를 수 있어요. 동기 팩토리는 값을 반환하거나 에러를 던지는 순간, 비동기 팩토리는 반환한 `Promise`가 확정(settle)되는 순간 등록 창구가 닫혀요. 팩토리가 끝난 뒤에 호출하면 `onDispose can only be called while the factory is running`을 던지고, 종료가 시작된 뒤에 호출하면 `Cannot register cleanup after the app has stopped`를 던져요.
- **`void` 또는 `Promise<void>`만 반환하기:** 정리 훅은 반드시 `void` 또는 `Promise<void>`만 반환해야 해요. 다른 값(혹은 `void`가 아닌 값으로 이행되는 `Promise`)을 반환하면 실수로 반환값이 새어 나가지 않도록 TypeScript 컴파일 에러가 발생해요. Node의 `http.Server.close()`처럼 `Server` 객체를 반환하는 종료 메서드는 `onDispose(() => { server.close() })`처럼 중괄호로 한 번 감싸 주세요.
- **훅 안에서 `await app.stop()` 호출 금지:** 정리 훅 자체가 `stop()` 완료 과정의 일부이기 때문에 `onDispose()` 안에서 `app.stop()`을 `await`하면 영원히 데드락에 빠져요.
- **훅 에러와 `AggregateError`:** 중간에 한 훅이 예외를 던지거나 reject하더라도 `stop()`은 남은 훅들을 끝까지 모두 실행해요. 실패가 하나뿐이면 그 에러를 그대로 다시 던지고, 두 개 이상 실패하면 `AggregateError`(`App stop failed`)로 묶어서 거부해요.
- **`start()` 실패 시 자동 롤백:** 앱을 띄우는 도중 `app.start()`가 실패하면 그때까지 등록된 리소스를 치우기 위해 자동으로 `stop()`을 먼저 호출한 뒤 reject해요. 에러가 하나면 그대로 전달하고, 기동과 정리 양쪽 모두 실패하면 `AggregateError`(`App startup and stop failed`)로 거부해요. 단, 일단 `start()`가 성공한 뒤 앱 런타임 도중에 발생하는 일반 에러는 그래프를 자동으로 멈추지 **않아요**.

<Callout kind="caution" title="stop()이 하지 않는 일">

`stop()`은 이후의 `inject()` 호출을 막고 등록된 `onDispose` 훅을 실행할 뿐이에요. 분리된 미완료 팩토리를 기다리거나, 진행 중인 I/O를 취소하거나, 이미 변수에 들고 있는 JavaScript 객체를 무효화하지는 **않아요**. 새 요청 유입 차단, `AbortController.abort()` 호출, 우아한 종료 순서 제어는 애플리케이션 코드에서 직접 챙겨 주세요.

</Callout>
