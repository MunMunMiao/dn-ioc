## 계층별 import 규칙

건강한 MVC 코드베이스에서는 `import`가 항상 위에서 아래로만 흘러요. 컨트롤러가 서비스를 건너뛰어 테이블을 직접 조회하지 않고, 리포지토리가 HTTP 컨트롤러를 거꾸로 `import`하지도 않죠.

| 계층 | 파일 | 내보내는 항목 | 허용된 프로젝트 내부 import | 역할과 책임 |
| --- | --- | --- | --- | --- |
| **Models** | `models/user.ts` | `type User` | 없음 | 공유 TypeScript 인터페이스와 데이터 모양 정의. |
| **Database** | `db/database.ts` | `databaseRef` | 없음 | 커넥션 풀을 소유하고 `onDispose()` 정리 훅을 등록해요. |
| **Repositories** | `repositories/user-repository.ts` | `userRepositoryRef` | `db/`, `models/` | 컬렉션/SQL 쿼리를 타입이 지정된 메서드 뒤로 캡슐화해요. |
| **Services** | `services/user-service.ts` | `userServiceRef` | `repositories/`, `models/` | 입력값 검증과 도메인 규칙(`Invalid email`, 중복 이메일)을 처리해요. |
| **Controllers** | `controllers/user-controller.ts` | `userControllerRef` | `services/`, `models/` | HTTP/RPC 입력을 서비스 호출과 상태 코드로 변환해요. |
| **Entrypoint** | `main.ts` | `app` | `controllers/`, `db/` | 상태를 가진 공유 `Ref`를 루트에 고정하고 앱을 기동해요. |

## 전체 MVC 그래프 아래에서 위로 따라가기

여섯 개의 파일 탭을 맨 아래 계층부터 위로 넘기면서 요청 하나가 그래프를 어떻게 통과하는지 따라가 보세요.

1. **`db/database.ts`:** `provide(function Database({ onDispose }) { ... })`처럼 기명 함수를 써서 순환 참조 진단 메시지에 `<anonymous>` 대신 `Database`가 찍히도록 했고, 닫아야 할 상태 바로 옆에서 `onDispose` 훅을 등록했어요.
2. **`models/user.ts`:** 순수 TypeScript `interface User`만 들어 있어요. DI 관련 `import`는 하나도 필요 없죠.
3. **`repositories/user-repository.ts`:** `userRepositoryRef`는 팩토리가 실행될 때 `inject(databaseRef)`를 한 번 호출해 `'users'` 컬렉션을 가져오고 `{ findByEmail, create }` 메서드를 반환해요.
4. **`services/user-service.ts`:** `userServiceRef`는 `userRepositoryRef`를 주입받아 이메일 형식 검사와 중복 체크 로직을 HTTP 핸들러 바깥으로 깔끔하게 분리해요.
5. **`controllers/user-controller.ts`:** `userControllerRef`는 `userServiceRef`를 주입받아 `{ status: 201, body }` 응답 형태를 조립해요.
6. **`main.ts`:** `bootstrapApp()`이 루트 스코프에 `providers: [databaseRef]`를 설치하고 시작 콜백 안에서 `userControllerRef`를 `inject()`해요.

## 커넥션 풀을 루트 providers에 명시해야 하는 이유

여기서 이런 궁금증이 들 수 있어요. "`databaseRef`도 `provide()`로 만들었으니, `main.ts`에서 `providers: [databaseRef]`를 빼더라도 `userRepositoryRef` 안의 `inject(databaseRef)`가 알아서 설치해 주지 않나요?"

단일 스코프만 쓰는 단순한 앱이라면 맞아요. 루트 스코프에서 처음 `inject(databaseRef)`가 호출될 때 거기에 캐시될 테니까요. **그럼에도 `main.ts`에 `providers: [databaseRef]`를 명시해 두면 앱이 커질 때 든든한 안전장치가 돼요.**

- [프로바이더와 Ref](/ko/providers/)와 [스코프와 프라이빗 서브트리](/ko/scopes/)에서 봤듯이, 미리 등록되지 않은 `Ref`는 *가장 먼저 `inject()`를 호출한 스코프* 안에 스스로 설치돼요.
- 만약 나중에 어드민 라우터와 백그라운드 잡 워커처럼 격리된 `{ providers }` 서브트리 두 개를 띄웠는데 상위 스코프 어디에도 `databaseRef`가 등록되어 있지 않다면, 두 서브트리가 조용히 **각자 별도의 커넥션 풀**을 열게 돼요.
- 상태를 가진 리소스(`databaseRef`, Redis 클라이언트, 요청 제한 저장소 등)를 루트 `providers`에 고정해 두면 지연 생성의 이점은 그대로 누리면서, 프로세스 안의 모든 서브트리가 단 하나의 풀을 공유하고 `await app.stop()` 시점에 딱 한 번 닫히도록 보장할 수 있어요.

## 새 리소스 모듈을 추가하는 작업 흐름

여기에 두 번째 기능으로 `posts`를 추가한다고 해 볼게요. 기존 `user` 모듈은 전혀 건드릴 필요 없이 예측 가능한 네 단계만 밟으면 돼요.

1. **모델 추가 (`models/post.ts`):** `interface Post { id: string; authorId: string; title: string }`을 내보내요.
2. **리포지토리 추가 (`repositories/post-repository.ts`):** 기존 `databaseRef`를 주입받는 `postRepositoryRef = provide(function PostRepository({ inject }) { ... })`를 내보내요.
3. **서비스 추가 (`services/post-service.ts`):** `postRepositoryRef`(작성자 존재 여부를 확인해야 한다면 `userRepositoryRef`까지)를 주입받는 `postServiceRef = provide(function PostService({ inject }) { ... })`를 내보내요.
4. **컨트롤러 연결 (`controllers/post-controller.ts` → `main.ts`):** `postControllerRef`를 내보내고 `main.ts`에서 라우트를 연결할 때 `inject(postControllerRef)`를 호출해요.

무엇을 *건드리지 않았는지* 확인해 보세요. 리포지토리와 서비스를 하나 만들 때마다 중앙 DI 목록 파일을 열어 수정할 필요가 없고, `databaseRef`는 이미 루트에서 안전하게 공유되고 있어요.

## 단위 테스트에서 userRepositoryRef 갈아끼우기

`userServiceRef`가 `userRepositoryRef`를 직접 `import`하고 있더라도, `UserService`만 격리해서 테스트하기 위해 모듈 단위 모킹(`vi.mock`이나 `mock.module`)을 쓸 필요는 없어요. 테스트의 `bootstrapApp()`에 `provideFor(userRepositoryRef, fakeUserRepository)` 한 줄만 넘겨주면 돼요.

- `userServiceRef`는 실제 리포지토리 대신 인메모리 `Map`으로 만든 가짜 리포지토리를 전달받아요.
- `userRepositoryRef`의 기본 팩토리가 아예 실행되지 않기 때문에, 테스트 도중 `databaseRef`는 인스턴스화조차 되지 않아요.

<Callout kind="caution" title="단위 테스트에서 미처 모킹하지 않은 Ref를 주의하세요">

모든 `Ref`는 실제로 동작하는 기본 팩토리를 품고 있기 때문에, MVC 단위 테스트에서 실수로 `provideFor(someOtherRef, fake)`를 빼먹더라도 **에러가 나지 않고** 실제 구현체가 조용히 실행돼요. 핵심 비즈니스 로직에서 DB나 외부 SDK `import`를 아예 걷어내고, 테스트에서 가짜 구현을 빠뜨렸을 때 즉시 에러로 알려 주길 원한다면 다음 장인 [DDD와 클린 아키텍처](/ko/ddd/)를 살펴보세요.
