## Deno에서 설치 없이 바로 쓰기

가볍게 단일 파일 Deno 스크립트를 짜는데 굳이 `deno.json`부터 만들고 싶지 않을 때가 있죠? Deno에서는 `npm:` 지정자로 `dn-ioc`를 바로 `import`할 수 있어요.

<Code
  title="deno-import.ts"
  lang="ts"
  code={`import { bootstrapApp, provide, provideFor, token } from 'npm:dn-ioc'`}
/>

## 브라우저 CDN과 Import Map

웹 페이지에서 `dn-ioc`를 쓰기 위해 꼭 번들러를 띄울 필요는 없어요. 최신 브라우저라면 CDN에서 압축된 ESM 빌드를 직접 불러올 수 있거든요.

| CDN | URL | 제공하는 파일 |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc` | `index.min.js` (`4.8 kB`, gzip `1.9 kB`) |
| unpkg | `https://unpkg.com/dn-ioc` | `index.min.js` — 완전히 동일한 파일 |
| esm.sh | `https://esm.sh/dn-ioc` | esm.sh가 자체 변환한 빌드 |

버전 태그를 생략하면 CDN이 최신 릴리스를 내려줘요. 운영 페이지에서 특정 버전으로 고정하고 싶다면 패키지 이름 뒤에 원하는 버전을 붙여 주세요.

여기에 `<script type="importmap">`을 곁들이면 모듈 코드 안에서 `'dn-ioc'`라는 짧은 이름을 그대로 유지할 수 있어서, 번들러가 있든 없든 똑같은 코드가 그대로 돌아가요.

<CodeTabs
  files={[

<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc"

## ESM 및 TypeScript 설정

`dn-ioc`는 **ESM 전용**이에요. CommonJS의 `require()` 대신 항상 `import` 문으로 불러와 주세요.

TypeScript 프로젝트에서는 `tsconfig.json`에 `"moduleResolution": "bundler"`를 설정하면 돼요. 요즘 많이 쓰는 Vite, Bun, Deno, Next.js, Astro, `tsdown` 환경이라면 이미 기본값으로 켜져 있을 거예요.

<Code
  title="tsconfig.json"
  lang="json"
  code={`{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}`}
/>

<Callout kind="caution" title="NodeNext와 Node16 타입 선언 해석은 지원하지 않아요">

`NodeNext` 및 `Node16` 선언 해석 모드는 **지원하지 않아요**. `dn-ioc`를 타입 체크하는 TypeScript 설정에서는 `"moduleResolution": "bundler"`를 유지해 주세요.

</Callout>
