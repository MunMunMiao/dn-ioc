`dn-ioc` 是一個輕量、零外部相依性的純 ESM 套件，一行指令就能裝好，完全不會在 `node_modules` 裡塞進一堆來路不明的間接相依套件。不管團隊平常習慣哪套套件管理工具都能直接安裝，在 Deno 透過 `npm:` 或是在瀏覽器直接從 CDN 載入也同樣順手。

<Code
  title="install.sh"
  lang="bash"
  code={`npm install dn-ioc
pnpm add dn-ioc
yarn add dn-ioc
bun add dn-ioc
deno add npm:dn-ioc`}
/>

## 在 Deno 免安裝直接匯入

只是想隨手寫一支單檔 Deno 腳本，懶得先建 `deno.json` 嗎？Deno 可以直接透過 `npm:` 前綴匯入 `dn-ioc`。

<Code
  title="deno-import.ts"
  lang="ts"
  code={`import { bootstrapApp, provide, provideFor, token } from 'npm:dn-ioc'`}
/>

## 瀏覽器 CDN 與 Import Maps

在網頁前端使用 `dn-ioc` 不見得非得先架設打包工具（bundler）不可。現代瀏覽器可以直接從 CDN 載入壓縮好的 ESM 建置產物：

| CDN | 網址 | 實際提供的檔案 |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc` | `index.min.js`（壓縮後的 ESM 建置檔） |
| unpkg | `https://unpkg.com/dn-ioc` | `index.min.js` —— 與上方為完全同一個檔案 |
| esm.sh | `https://esm.sh/dn-ioc` | esm.sh 自行轉譯打包的版本 |

不加版本號時，CDN 會直接回應最新版本；正式環境如果想鎖定特定版本，再自行於套件名稱後補上版本標籤即可。

搭配 `<script type="importmap">` 使用，就能在模組裡保留乾淨的 `'dn-ioc'` 裸模組匯入寫法，不論有沒有經過打包工具都能共用同一份程式碼。

<Code
  title="importmap.html"
  lang="html"
  code={`<!doctype html>
<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc"
        }
      }
    </script>
  </head>
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'dn-ioc'

      const greetingRef = provide(() => 'hello, browser')
      const app = bootstrapApp(({ inject }) => {
        document.body.textContent = inject(greetingRef)
      })

      await app.start()
    </script>
  </body>
</html>`}
/>

<Code
  title="direct-cdn.html"
  lang="html"
  code={`<!doctype html>

  <body>

## ESM 與 TypeScript 設定

`dn-ioc` **僅提供純 ESM 格式**——請一律使用標準 `import` 語法匯入，不要使用舊式的 CommonJS `require()`。

在 TypeScript 專案中，請將 `tsconfig.json` 裡的 `"moduleResolution"` 設為 `"bundler"`。目前主流的 Vite、Bun、Deno、Next.js、Astro 與 `tsdown` 專案範本預設都已經採用這個模式，基本上不用額外調整。

<Code
  title="tsconfig.json"
  lang="json"
  code={`{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}`}
/>

<Callout kind="caution" title="關於 NodeNext 與 Node16 型別宣告解析">

`dn-ioc` **不支援** `NodeNext` 與 `Node16` 的型別宣告解析模式。凡是需要對 `dn-ioc` 進行型別檢查的 TypeScript 設定檔，請維持 `"moduleResolution": "bundler"`。

</Callout>

因為核心完全不碰 `process`、DOM API 與計時器，你寫好的每個 provider 都能在 Node.js、Bun、Deno、瀏覽器、Web Worker 與邊緣執行環境之間 100% 無痛移植。
