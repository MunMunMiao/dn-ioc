`dn-ioc` se distribuye como paquete ESM sin dependencias (`4.8 kB` minificado, `1.9 kB` con gzip), así que instalarlo lleva un solo comando y no arrastra nada extra a tu `node_modules`. Instálalo con el gestor de paquetes que ya uses en tu proyecto, o impórtalo directo con `npm:` en Deno o desde un CDN en el navegador.

<Code
  title="install.sh"
  lang="bash"
  code={`npm install dn-ioc
pnpm add dn-ioc
yarn add dn-ioc
bun add dn-ioc
deno add npm:dn-ioc`}
/>

## Sin instalación previa en Deno

¿Quieres levantar un script rápido de un solo archivo en Deno sin ponerte a configurar primero un `deno.json`? Deno puede importar `dn-ioc` directamente mediante el especificador `npm:`.

<Code
  title="deno-import.ts"
  lang="ts"
  code={`import { bootstrapApp, provide, provideFor, token } from 'npm:dn-ioc'`}
/>

## CDN en navegador e Import Maps

Tampoco necesitas un bundler para usar `dn-ioc` en una página web. Los navegadores modernos cargan la versión ESM minificada directamente desde un CDN:

| CDN | URL | Qué sirve |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc` | `index.min.js` (`4.8 kB`, `1.9 kB` con gzip) |
| unpkg | `https://unpkg.com/dn-ioc` | `index.min.js` — exactamente el mismo archivo |
| esm.sh | `https://esm.sh/dn-ioc` | Build transpilado propio de esm.sh |

Sin sufijo de versión, el CDN sirve la última publicación; en producción, añade una etiqueta de versión explícita si quieres fijar una entrega concreta.

Si añades un `<script type="importmap">`, podrás seguir escribiendo imports limpios con `'dn-ioc'` en tus módulos, de modo que el mismo código funcione con o sin bundler.

<Code
  title="importmap.html"
  lang="html"
  code={`<!doctype html>
<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc"
        }
      }
    </script>
  </head>
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'dn-ioc'

      const greetingRef = provide(() => 'hello, browser')
      const app = bootstrapApp(({ inject }) => {
        document.body.textContent = inject(greetingRef)
      })

      await app.start()
    </script>
  </body>
</html>`}
/>

## Configuración de ESM y TypeScript

`dn-ioc` es **exclusivamente ESM**: cárgalo siempre con `import`, nunca con el `require()` de CommonJS.

En proyectos TypeScript, usa `"moduleResolution": "bundler"` en tu `tsconfig.json`. Herramientas modernas como Vite, Bun, Deno, Next.js, Astro y `tsdown` ya traen este modo activado de serie.

<Code
  title="tsconfig.json"
  lang="json"
  code={`{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}`}
/>

<Callout kind="caution" title="Resolución de tipos con NodeNext y Node16">

La resolución de declaraciones con `NodeNext` y `Node16` **no está soportada**. Mantén `"moduleResolution": "bundler"` en los archivos `tsconfig.json` que verifiquen tipos contra `dn-ioc`.

</Callout>

Como el núcleo no toca `process`, APIs del DOM ni temporizadores, tus providers son 100 % portables entre Node.js, Bun, Deno, navegadores, Web Workers y entornos edge.

## Instalar el Skill para agentes de IA

Si trabajas con agentes de código como Claude Code, Codex, Cursor, Antigravity o Gemini CLI, puedes instalar el Skill oficial en inglés (`skills/dn-ioc/SKILL.md`) para que el agente conozca la API pública exacta, la regla entre `Ref` y `Token`, el ciclo de vida y los mensajes de error literales sin inventar decoradores ni contenedores globales:

<Code
  title="install-skill.sh"
  lang="bash"
  code={`npx skills add MunMunMiao/dn-ioc
bunx skills add MunMunMiao/dn-ioc`}
/>
