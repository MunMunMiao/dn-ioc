`dn-ioc` se distribuye como un paquete ESM ligero y sin dependencias, así que instalarlo lleva un solo comando y no arrastra nada extra a tu `node_modules`. Instálalo con el gestor de paquetes que ya uses en tu proyecto, o cárgalo directamente desde un CDN en el navegador.

## CDN en navegador e Import Maps

Tampoco necesitas un bundler para usar `dn-ioc` en una página web. Los navegadores modernos cargan la versión ESM minificada directamente desde un CDN:

| CDN | URL | Qué sirve |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc` | `index.min.js` (compilación ESM minificada) |
| unpkg | `https://unpkg.com/dn-ioc` | `index.min.js` — exactamente el mismo archivo |
| esm.sh | `https://esm.sh/dn-ioc` | Build transpilado propio de esm.sh |

Sin sufijo de versión, el CDN sirve la última publicación; en producción, añade una etiqueta de versión explícita si quieres fijar una entrega concreta.

Si añades un `<script type="importmap">`, podrás seguir escribiendo imports limpios con `'dn-ioc'` en tus módulos, de modo que el mismo código funcione con o sin bundler.

```html title="importmap.html"
<!doctype html>
<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc"
        }
      }
    </script>
  </head>
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'dn-ioc'

      const greetingRef = provide(() => 'hello, browser')
      const app = bootstrapApp(({ inject }) => {
        document.body.textContent = inject(greetingRef)
      })

      await app.start()
    </script>
  </body>
</html>
```

```html title="direct-cdn.html"
<!doctype html>
<html lang="en">
  <body>
    <script type="module">
```

## Configuración de ESM y TypeScript

`dn-ioc` es **exclusivamente ESM**: cárgalo siempre con `import`, nunca con el `require()` de CommonJS.

En proyectos TypeScript, usa `"moduleResolution": "bundler"` en tu `tsconfig.json`. Herramientas modernas como Vite, Bun, Next.js, Astro y `tsdown` ya traen este modo activado de serie.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}
```

<Callout kind="caution" title="Resolución de tipos con NodeNext y Node16">

La resolución de declaraciones con `NodeNext` y `Node16` **no está soportada**. Mantén `"moduleResolution": "bundler"` en los archivos `tsconfig.json` que verifiquen tipos contra `dn-ioc`.

</Callout>

Como el núcleo no toca `process`, APIs del DOM ni temporizadores, tus providers son 100 % portables entre Node.js, Bun, navegadores, Web Workers y entornos edge.
