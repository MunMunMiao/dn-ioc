`dn-ioc` は軽量かつ依存ゼロの単一 ESM パッケージとして配布されています。コマンド1つで入りますし、`node_modules` に余計な間接依存を持ち込むこともありません。普段プロジェクトで使っているパッケージマネージャで入れるのはもちろん、Deno の `npm:` 指定子やブラウザの CDN から直接読み込むこともできます。

<Code
  title="install.sh"
  lang="bash"
  code={`npm install dn-ioc
pnpm add dn-ioc
yarn add dn-ioc
bun add dn-ioc
deno add npm:dn-ioc`}
/>

## Deno ならインストールすら不要

ちょっとした単一ファイルの Deno スクリプトを試したいだけで、わざわざ `deno.json` を作りたくないときもありますよね。Deno なら `npm:` 指定子でそのまま `dn-ioc` を import できます。

<Code
  title="deno-import.ts"
  lang="ts"
  code={`import { bootstrapApp, provide, provideFor, token } from 'npm:dn-ioc'`}
/>

## ブラウザ CDN と Import Maps

Web ページで `dn-ioc` を使うのにバンドラは必須ではありません。モダンブラウザなら、CDN から配信されている minify 済み ESM ビルドをそのまま読み込めます。

| CDN | URL | 配信される中身 |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc` | `index.min.js`（minify 済み ESM ビルド） |
| unpkg | `https://unpkg.com/dn-ioc` | `index.min.js` — 上とまったく同じファイル |
| esm.sh | `https://esm.sh/dn-ioc` | esm.sh 側でトランスパイルされたビルド |

バージョン指定を省くと CDN は常に最新リリースを配信します。本番ページで特定バージョンに固定したい場合は、パッケージ名の後ろにバージョンタグを付けてください。

また、`<script type="importmap">` を書いておけば、モジュール側のコードを `'dn-ioc'` のベア指定子のまま統一できるので、バンドラあり・なしのどちらでも同じコードがそのまま動きます。

<Code
  title="importmap.html"
  lang="html"
  code={`<!doctype html>
<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc"
        }
      }
    </script>
  </head>
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'dn-ioc'

      const greetingRef = provide(() => 'hello, browser')
      const app = bootstrapApp(({ inject }) => {
        document.body.textContent = inject(greetingRef)
      })

      await app.start()
    </script>
  </body>
</html>`}
/>

<Code
  title="direct-cdn.html"
  lang="html"
  code={`<!doctype html>
<html lang="en">
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'https://cdn.jsdelivr.net/npm/dn-ioc'

## ESM と TypeScript の設定

`dn-ioc` は **ESM 専用** です。CommonJS の `require()` ではなく、必ず `import` で読み込んでください。

TypeScript プロジェクトでは、`tsconfig.json` の `"moduleResolution"` に `"bundler"` を指定します。最近の Vite、Bun、Deno、Next.js、Astro、`tsdown` などの環境なら、最初からこの設定になっているはずです。

<Code
  title="tsconfig.json"
  lang="json"
  code={`{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}`}
/>

<Callout kind="caution" title="NodeNext / Node16 の型解決には非対応です">

`NodeNext` および `Node16` の型定義解決は **サポートしていません**。`dn-ioc` を型チェックする TypeScript 設定では、`"moduleResolution": "bundler"` を使ってください。

</Callout>

カーネル内部で `process` や DOM API、タイマーに一切依存していないおかげで、書いたプロバイダは Node.js、Bun、Deno、ブラウザ、Web Worker、エッジランタイムの間で 100% そのまま使い回せます。

## AI エージェント向け Skill のインストール

Claude Code、Codex、Cursor、Antigravity、Gemini CLI などの AI コーディングエージェントを使っている場合は、公式の英語 Skill（`skills/dn-ioc/SKILL.md`）を入れておくと便利です。公開 API、`Ref` と `Token` の使い分け、ライフサイクル規約、正確なエラー文字列まで共有できるので、存在しないデコレータやコンテナを勝手に作られる心配がなくなります。

<Code
  title="install-skill.sh"
  lang="bash"
  code={`npx skills add MunMunMiao/dn-ioc
bunx skills add MunMunMiao/dn-ioc`}
/>

プレーンテキスト1枚でコンテキストを渡したいツールには、[`/llms.txt`](/llms.txt) をそのまま指定してください。

準備ができたら、さっそく [5分クイックスタート](/ja/quickstart/) で最初のアプリを動かしてみましょう。
