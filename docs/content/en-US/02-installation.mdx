`dn-ioc` ships as a zero-dependency ESM package (`4.8 kB` minified, `1.9 kB` gzipped), so installing it takes one command and brings zero transitive baggage into `node_modules`. Grab it with whichever package manager your project already uses, or pull it straight from `npm:` on Deno or a CDN in the browser.

## Zero-Install on Deno

Spinning up a single-file Deno script and don't feel like setting up a `deno.json` first? Deno can import `dn-ioc` straight through its `npm:` specifier—pin `@0.3.1` so future runs always pull the exact version you tested against.

<Code
  title="deno-import.ts"
  lang="ts"
  code={`import { bootstrapApp, provide, provideFor, token } from 'npm:dn-ioc@0.3.1'`}
/>

## Browser CDN & Import Maps

You don't need a bundler to use `dn-ioc` in a web page. Modern browsers can load the minified ESM build directly from a CDN:

| CDN | Pinned URL | What it serves |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc@0.3.1` | `index.min.js` (`4.8 kB`, `1.9 kB` gzipped) |
| unpkg | `https://unpkg.com/dn-ioc@0.3.1` | `index.min.js` — exact same file |
| esm.sh | `https://esm.sh/dn-ioc@0.3.1` | esm.sh's own transpiled build |

Always pin a version like `@0.3.1` in browser URLs—dropping the version tag tells the CDN to serve whatever release is newest, which can surprise a live page.

Adding a `<script type="importmap">` lets you keep bare `'dn-ioc'` imports in your modules, so the exact same code runs with or without a bundler.

<CodeTabs
  files={[
    {
      title: 'importmap.html',
      lang: 'html',
      code: `<!doctype html>
<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc@0.3.1"
        }
      }
    </script>
  </head>
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'dn-ioc'

      const greetingRef = provide(() => 'hello, browser')
      const app = bootstrapApp(({ inject }) => {
        document.body.textContent = inject(greetingRef)
      })

      await app.start()
    </script>
  </body>
</html>`,

## ESM & TypeScript Configuration

`dn-ioc` is **ESM-only**—always load it with `import` rather than CommonJS `require()`.

In TypeScript projects, set `"moduleResolution": "bundler"` in your `tsconfig.json`. Modern Vite, Bun, Deno, Next.js, Astro, and `tsdown` setups already use this mode by default.

<Code
  title="tsconfig.json"
  lang="json"
  code={`{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}`}
/>

<Callout kind="caution" title="NodeNext and Node16 declaration resolution">

`NodeNext` and `Node16` declaration resolution are **not supported**. Keep `"moduleResolution": "bundler"` in TypeScript configs that type-check against `dn-ioc`.

</Callout>
