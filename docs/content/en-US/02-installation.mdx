## Browser CDN & Import Maps

You don't need a bundler to use `dn-ioc` in a web page. Modern browsers can load the minified ESM build directly from a CDN:

| CDN | URL | What it serves |
| --- | --- | --- |
| jsDelivr | `https://cdn.jsdelivr.net/npm/dn-ioc` | `index.min.js` (minified ESM build) |
| unpkg | `https://unpkg.com/dn-ioc` | `index.min.js` — exact same file |
| esm.sh | `https://esm.sh/dn-ioc` | esm.sh's own transpiled build |

Without a version suffix, CDNs serve the latest release; in production, append an explicit version tag if you want to lock a page to a specific release.

Adding a `<script type="importmap">` lets you keep bare `'dn-ioc'` imports in your modules, so the exact same code runs with or without a bundler.

```html title="importmap.html"
<!doctype html>
<html lang="en">
  <head>
    <script type="importmap">
      {
        "imports": {
          "dn-ioc": "https://cdn.jsdelivr.net/npm/dn-ioc"
        }
      }
    </script>
  </head>
  <body>
    <script type="module">
      import { bootstrapApp, provide } from 'dn-ioc'

      const greetingRef = provide(() => 'hello, browser')
      const app = bootstrapApp(({ inject }) => {
        document.body.textContent = inject(greetingRef)
      })

      await app.start()
    </script>
  </body>
</html>
```

## ESM & TypeScript Configuration

`dn-ioc` is **ESM-only**—always load it with `import` rather than CommonJS `require()`.

In TypeScript projects, set `"moduleResolution": "bundler"` in your `tsconfig.json`. Modern Vite, Bun, Next.js, Astro, and `tsdown` setups already use this mode by default.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "strict": true
  }
}
```

<Callout kind="caution" title="NodeNext and Node16 declaration resolution">

`NodeNext` and `Node16` declaration resolution are **not supported**. Keep `"moduleResolution": "bundler"` in TypeScript configs that type-check against `dn-ioc`.

</Callout>

Because the kernel avoids `process`, DOM APIs, and timers, your providers stay 100% portable across Node.js, Bun, browsers, Web Workers, and edge runtimes.
